= Migrar uma VM de armazenamento de um cluster ASA para um cluster ASA R2.
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
A partir do ONTAP 9.18.1, você pode migrar, sem interrupções, uma máquina virtual (VM) de storage de qualquer cluster ASA padrão para qualquer cluster ASA r2, para adotar a arquitetura simplificada e otimizada dos sistemas ASA r2 para ambientes somente SAN.


NOTE: Você não pode migrar uma máquina virtual de armazenamento de um ASA MetroCluster para um cluster ASA r2. Os sistemas ASA r2 não suportam configurações MetroCluster.

Os sistemas ASA r2 suportam a tecnologia QuickAssist (QAT). Os sistemas ASA não suportam QAT. A partir do ONTAP 9.20.1, o ONTAP reduz a alta latência de leitura e o uso da CPU que podem ocorrer após a migração de uma máquina virtual de storage de um sistema ASA (sem QAT) para um sistema ASA r2 (com QAT).

A migração de máquinas virtuais de armazenamento entre sistemas de armazenamento ASA e ASA R2 é suportada da seguinte forma:

[cols="2"]
|===
| De qualquer um dos seguintes sistemas ASA : | Para qualquer um dos seguintes sistemas ASA r2: 


 a| 
* ASA C800
* ASA C400
* ASA C250
* ASA A900
* ASA A800
* ASA A400
* ASA A250
* ASA A150
* ASA AFF A800
* ASA AFF A700
* ASA AFF A400
* ASA AFF A250
* ASA AFF A220

 a| 
* ASA A1K
* ASA C30
* ASA A90
* ASA A70
* ASA A50
* ASA A30
* ASA A20


|===
Para obter a lista mais atualizada de sistemas ASA e ASA r2, consultelink:https://hwu.netapp.com/["NetApp Hardware Universe"^] .  Os sistemas ASA r2 estão listados no NetApp Hardware Universe como "ASA Série A/Série C (Novo)".

Você só pode migrar uma VM de storage para um cluster ASA r2 a partir de um cluster ASA. Não há suporte para a migração de qualquer outro tipo de sistema ONTAP para um sistema ASA r2.

.Antes de começar
Todos os nós do cluster ASA r2 e o próprio cluster ASA devem estar executando o ONTAP 9.18.1 ou posterior.  As versões de patch do ONTAP 9.18.1 nos nós do cluster podem variar.



[[step-1-verify-the-status-of-the-asa-storage-vm]]
== Etapa 1: Verifique o status da VM de armazenamento ASA

Antes de migrar uma VM de armazenamento de um sistema ASA , não deve haver namespaces NVMe ou vVols presentes, e cada volume na VM de armazenamento deve conter apenas um LUN.  A migração de namespaces NVMe e vVols não é suportada.  A arquitetura dos sistemas ASA r2 exige que os volumes contenham um único LUN.

.Passos
. Verifique se não há namespaces NVMe presentes na máquina virtual de armazenamento:
+
[source, cli]
----
vserver nvme namespace show -vserver <storage_VM>
----
+
Se as entradas forem exibidas, os objetos NVMe devem serlink:https://docs.netapp.com/us-en/ontap/nvme/convert-namespace-to-lun-task.html["convertido"^] para LUNs ou removidos.  Veja o `vserver nvme namespace delete` e o `vserver nvme subsystem delete` comandos nolink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Referência do comando ONTAP"^] Para obter mais informações.

. Verifique se não há vVols presentes na VM de armazenamento:
+
[source, cli]
----
lun show -vserver <storage_VM> -class protocol-endpoint,vvol
----
+
Caso existam vVols , eles devem ser copiados para outra VM de armazenamento e, em seguida, excluídos da VM de armazenamento a ser migrada.  Veja o `lun copy` e `lun delete` comandos nolink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Referência do comando ONTAP"^] Para obter mais informações.

. Verifique se cada volume na máquina virtual de armazenamento contém um único LUN:
+
[source, cli]
----
lun show -vserver <storage_VM>
----
+
Se um volume contiver mais de um LUN, use o `volume create` e `lun move` comandos para criar uma relação de volume para LUN de 1:1. Veja olink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Referência do comando ONTAP"^] para mais informações.



.O que vem a seguir?
Você está pronto para criar uma relação de pares de cluster entre seus clusters ASA e ASA R2.



[[step-2-create-a-cluster-peer-relationship-between-your-asa-and-asa-r2-clusters]]
== Etapa 2: Crie uma relação de pares de cluster entre seus clusters ASA e ASA R2.

Antes de migrar uma VM de armazenamento de um cluster ASA para um cluster ASA R2, você precisa criar uma relação de pares.  Uma relação ponto a ponto define conexões de rede que permitem que clusters ONTAP e máquinas virtuais de armazenamento troquem dados com segurança.

.Sobre esta tarefa
O cluster ASA é o cluster de _origem_ do qual a máquina virtual de storage será migrada, e o cluster ASA r2 é o cluster de _destino_ para o qual a máquina virtual de storage será migrada.

.Antes de começar
Você deve ter criado LIFs intercluster em todos os nós dos clusters que estão sendo interligados, usando um dos seguintes métodos.

* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-share-data-ports-task.html["Configure LIFs intercluster em portas de dados compartilhadas."^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-dedicated-ports-task.html["Configure LIFs intercluster em portas de dados dedicadas."^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-ports-own-networks-task.html["Configure LIFs entre clusters em espaços IP personalizados."^]


.Passos
. No cluster de destino, crie uma relação de peer com o cluster de origem e gere uma frase secreta:
+
[source, cli]
----
cluster peer create -peer-addrs <source_cluster_LIF_IPs> -generate-passphrase
----
+
O exemplo a seguir cria uma relação de pares entre o cluster 1 e o cluster 2 e gera uma senha automática pelo sistema:

+
[listing]
----
cluster1::> cluster peer create -peer-addrs 10.98.191.193 -generate-passphrase
Passphrase: UCa+6lRVICXeL/gq1WrK7ShR
            Peer Cluster Name: cluster2
            Initial Allowed Vserver Peers: -
            Expiration Time: 6/7/2017 09:16:10 +5:30
            Intercluster LIF IP: 10.140.106.185
Warning: make a note of the passphrase - it cannot be displayed again.

----
. Copie a senha gerada.
. No cluster de origem, crie uma relação de peering com o cluster de destino:
+
[source, cli]
----
cluster peer create -peer-addrs <destination_cluster_LIF_IPs>
----
. Insira a frase secreta gerada no cluster de destino.
. Verifique se a relação de pares do cluster foi criada:
+
[source, cli]
----
cluster peer show
----
+
O exemplo a seguir exibe a saída esperada para clusters emparelhados com sucesso.

+
[listing]
----
cluster1::> cluster peer show

Peer Cluster Name   Cluster Serial Number   Availability   Authentication
-----------------   ---------------------   -------------- --------------
cluster2             1-80-123456             Available      ok
----


.Resultado
Os clusters ASA e ASA R2 estão interligados e os dados das máquinas virtuais de armazenamento podem ser transferidos com segurança.

.O que vem a seguir?
Você está pronto para executar a verificação prévia da migração.



[[step-3-execute-the-migration-pre-check]]
== Etapa 3: execute a verificação prévia da migração

Antes de migrar uma VM de storage de um cluster ASA para um cluster ASA r2, você deve executar uma verificação prévia de migração e corrigir todos os problemas necessários. Você não pode executar a migração até que a verificação prévia seja concluída com sucesso.

.Sobre esta tarefa
O cluster ASA é o cluster de _origem_ do qual a máquina virtual de storage será migrada, e o cluster ASA r2 é o cluster de _destino_ para o qual a máquina virtual de storage será migrada.

.Passo
. No seu cluster de destino, execute a verificação prévia da migração:
+
[source, cli]
----
vserver migrate start -vserver <storage_VM> -source-cluster <sourcecluster> -check-only true
----
+
Se precisar corrigir algum problema para se preparar para a migração, o problema e a ação corretiva são exibidos. Corrija o problema e repita a verificação prévia até que ela seja concluída com sucesso.



.O que vem a seguir?
Você está pronto para migrar sua VM de armazenamento do seu cluster ASA para um cluster ASA R2.



[[step-4-migrate-an-asa-storage-vm-to-an-asa-r2-cluster]]
== Etapa 4: Migrar uma VM de armazenamento ASA para um cluster ASA R2

Após preparar o cluster ASA e criar a relação de pares necessária com o cluster ASA R2, você pode iniciar a migração da VM de armazenamento.

Ao realizar uma migração de VM de armazenamento, é uma prática recomendada deixar 30% de folga na CPU tanto no cluster ASA quanto no cluster ASA R2 para permitir a execução da carga de trabalho da CPU.

.Sobre esta tarefa
* Após a migração da VM de armazenamento, a E/S do cliente passa sem interrupções para o cluster de destino, e a VM de armazenamento no cluster ASA r2 é removida automaticamente. O cutover automático e a remoção automática da VM de armazenamento estão habilitados por padrão. Opcionalmente, você pode desabilitar uma ou ambas as opções e executá-las manualmente.
* O cluster ASA é o cluster de _origem_ do qual a máquina virtual de storage será migrada, e o cluster ASA r2 é o cluster de _destino_ para o qual a máquina virtual de storage será migrada.


.Antes de começar
* O cluster ASA r2 deve ter espaço livre suficiente para acomodar a VM de armazenamento migrada.
* Se a máquina virtual de armazenamento do ASA contiver volumes criptografados, o gerenciador de chaves integrado ou o gerenciador de chaves externo no sistema ASA r2 deverá ser configurado no nível do cluster.
* As seguintes operações não podem ser executadas no cluster ASA de origem:
+
** operações de failover
** WAFLIRON
** Impressão digital
** Movimentação, rehospedagem, clonagem, criação, conversão ou análise de volume




.Passos
. No cluster de destino, inicie a migração da máquina virtual de storage:
+
[source, cli]
----
vserver migrate start -vserver <storage_VM_name> -source-cluster <source_cluster>
----
+
Para desativar a transição automática, use o `-auto-cutover false` parâmetro. Para desativar a remoção automática da VM de armazenamento de origem, use o `-auto-source-cleanup false` parâmetro.

. Acompanhe o andamento da migração.
+
[source, cli]
----
vserver migrate show -vserver <storage_VM_name>
----
+
Se precisar pausar ou cancelar a migração antes do início da transição automática, use o `vserver migrate pause` e o `vserver migrate abort` comandos.  Você deve pausar a migração antes de cancelá-la.  Não é possível cancelar a migração após o início do processo de transição.

+
Se o cutover automático estiver ativado, quando a migração for concluída, o *status* será exibido como *migration-complete*. Se o cutover automático estiver desativado, o *status* será exibido como *Ready for source cleanup*.



.Resultado
A máquina virtual de storage é migrada do cluster ASA para o cluster ASA r2. O nome e o UUID da máquina virtual de storage, o nome da LIF de dados, o endereço IP e os nomes dos objetos, como o nome do volume, permanecem inalterados. O UUID dos objetos migrados na máquina virtual de storage é atualizado.

.O que vem a seguir?
Se você desativou o cutover automático e a remoção automática da VM de armazenamento, execute o cutover e a limpeza pós-migração para transferir manualmente seus clientes ASA para o cluster de destino e remover a VM de armazenamento do cluster ASA.



[[step-5-post-migration-cutover-and-cleanup]]
== Etapa 5: transição e limpeza pós-migração

Durante uma migração de VM de armazenamento entre clusters, a E/S do cliente passa para o cluster de destino, e a VM de armazenamento no cluster de origem é removida automaticamente. Se você optar por desativar a transferência e a remoção automáticas da VM de armazenamento de origem durante a migração, você precisará executar essas etapas manualmente após o status da migração atingir *Pronto para limpeza da origem*.



[[manually-cut-over-clients-after-a-storage-vm-migration]]
=== Faça a comutação manual dos clientes após uma migração de VM de storage

Se você desativar a transição automática de clientes durante a migração entre clusters de uma VM de armazenamento, depois que o relacionamento de migração estiver pronto para a transição, execute a transição manualmente para que a VM de armazenamento de destino possa fornecer dados aos clientes.

.Sobre esta tarefa
Execute esta tarefa a partir do cluster de destino.

.Passos
. Executar manualmente a migração do cliente:
+
[source, cli]
----
vserver migrate cutover -vserver <storage_VM_name>
----
. Verifique se a operação de transição foi concluída:
+
[source, cli]
----
vserver migrate show
----


.Resultado
Os dados estão sendo fornecidos aos seus clientes a partir da máquina virtual de storage no seu cluster de destino.

.O que se segue?
Agora você está pronto para remover a VM de storage do cluster de origem.



[[manually-remove-a-storage-vm-after-migration]]
=== Remover manualmente uma VM de storage após a migração

Se você desativar a limpeza automática da origem durante uma migração de VM de armazenamento entre clusters, após a conclusão da migração, remova a VM de armazenamento do cluster de origem para liberar o espaço de storage.

.Antes de começar
Seus clientes devem estar acessando dados a partir do cluster de destino.

.Passos
. No cluster de origem, verifique se o status da VM de armazenamento de origem é *Pronto para limpeza de origem*:
+
[source, cli]
----
vserver migrate show
----
. Remova a VM de armazenamento de origem:
+
[source, cli]
----
vserver migrate source-cleanup -vserver <storage_VM_name>
----


.Resultado
A máquina virtual de storage no seu cluster de origem é removida.
